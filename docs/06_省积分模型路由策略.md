# 省积分模型路由策略（2026-11-27 立项版）

> 背景：账号高级版，截图时积分余额 885.82；用户明确要求"尽量不消耗积分，根据本地和线上模型优势整合，用最省的"。
> 一句话策略：**本地能干就本地，本地干不了才上云，上云先挑 0.00x，再挑低倍率，判断不了就交人。**

---

## 1. 为什么这不是拍脑袋

| 依据 | 内容 | 出处 |
| --- | --- | --- |
| 官方规则 | 积分消耗 = 模型定价 × 任务复杂度；**无固定 1 积分 = N token 换算** | https://www.codebuddy.cn/docs/workbuddy/Credits |
| 官方额度 | 高级版基础 4000 + 限时加赠 5000 = 9000/月；**当月有效、不结转** | https://www.codebuddy.cn/docs/workbuddy/Pricing |
| 第三方实测 | 9000 积分 / 50h10m 耗尽 → 20.37 亿 token，缓存命中 95.66% | https://developer.baidu.com/article/detail.html?id=9962058 |
| 本地能力 | AgentFloor：A0/A/B 层开源模型追平旗舰（84–100%）；C/D/E 降到 36–59% | https://arxiv.org/abs/2605.00334 |
| 量化证据 | 8-bit 长任务平均掉 0.8%；4-bit 最高掉 59% 且工具幻觉翻倍 | https://arxiv.org/html/2505.20276 ; https://arxiv.org/html/2607.27275 |

**两个必须说清的不确定性**【推测】：
1. 22.6 万 token/积分 来自第三方高强度 Agent 循环样本（95.66% 缓存命中），不是官方值；用户实际命中率低时，同样积分能跑的 token 会明显减少。
2. 倍率→积分按线性外推仅用于**排序选模型**，不用于账单。

## 2. 三层决策（已编码进 `cost_router.py`）

```
输入任务 → 能力层判定（A0/A/B/C/D/E）
   ├─ A0/A/B      → 本地模型（0 积分）
   ├─ C 且本地高配 → 本地模型 + 闸门（0 积分）
   ├─ C/D/E 本地不足 → 云端：hy4_flash(0.00x) → glm53_flash(0.08x) → deepseek(0.11x) → glm54(0.69x)
   ├─ 需要视觉且本地 8B → 云端 hy4_flash（注意作图/视频另计费）
   └─ 未识别层 → 人工止损（不猜、不烧积分）
```

** Hy4 flash 限免窗口**：11/16–11/30，每日赠额度。今天 11/27，**只剩 3 天**。限免仅聊天类不扣积分；作图、视频、长文档分析照扣。

## 3. 本地与云端各自该干什么（分工表）

| 任务类型 | 谁做 | 理由 |
| --- | --- | --- |
| 任务分类 / 路由 | **本地** | A0/A 层，开源模型 96–100% |
| 字段抽取 / 格式化 | **本地** | A 层，96% |
| 单步工具调用 / 两步链 | **本地** | A/B 层，84–96% |
| 短文本总结 / 改写 | **本地** | A/B 层，短上下文足够 |
| 代码补全（单文件） | **本地 8-bit** | 量化证据：8-bit 近无损；4-bit 掉链 |
| 多源冲突 / 长程规划 | **云端或人工** | C/D/E 层本地 36–59%，不可靠 |
| 视觉 / GUI 操作 | **云端或专用模型** | 本地 8B 无可靠视觉 |
| 精确计算 / 长序列 | **代码工具，不靠模型** | Illusion of Thinking：精确计算是崩溃区 |

## 4. 省积分的四个工程动作（已落地）

1. **本地优先路由**：`CostAwareRouter.decide()` 对 A0/A/B 直接返 `LOCAL`，estimated_credits=0。
2. **限免优先**：高能力层先选 `hy4_flash`（0.00x），并记录 reason 进台账。
3. **思考预算开关**：`budget_for_role()` 让 fast_router/extractor 关思考，避免简单任务烧 token。
4. **亲和队列**：`ModelAffinityQueue` 同模型聚批，减少换模开销（本机单卡尤其重要）。
