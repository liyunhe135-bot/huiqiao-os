# 规格工坊（Spec-First，Spec Kit/OpenSpec 式）

## 触发
新积木开工、新任务需求、任何「客户输入问题」进入构建前。

## 输入
需求描述（一句话到一段话均可，可含文件引用）。

## 步骤
1. **澄清门**：歧义点最多问 5 个定向问题，答案写回 spec（禁止无限追问）。
2. **spec.md**：写 what/why（用户行为与目标，不写技术栈）；交付物定义（是什么形态：代码/文档/表格/网页）；**AC 列表**——每条格式 `AC-n 给定…，当…，则…`，含至少 1 条负例。
3. **plan.md**：技术方案要点 + 风险；技术栈选型在此阶段定。
4. **tasks.md**：按依赖排序的编号任务清单；每任务带「验证命令/验证方式」；单任务预估 ≤ 半天。
5. 三件套交给汇桥（大脑）终审后冻结；**冻结后 AC 变更需人工确认**。

## 验证
- AC 可观察、可复现、含负例（禁止「应该/尽量/性能良好」）。
- tasks 每步有验证命令。

## 坑
- 不要在 spec 阶段写实现细节。
- 不要把「澄清问题」塞进 spec 正文（放 Q&A 附录）。
- 不要让 agent 自己在 checklist 上打勾（checklist 由评审者勾）。
