# 测试器（Test & Golden Eval）

## 触发
新模块需要测试、或一次真实 bug 修复后需要固化为回归题。

## 输入
模块契约/接口 + 一次真实失败样例（如有）。

## 步骤
1. **单测**：按契约的正例 + 负例 + 边界各写断言（本地跑通才交）。
2. **fail-to-pass 用例**：真实 bug → 先写必失败的测试 → 修复 → 转绿（金标准题，附参考解）。
3. **金标准登记**：题目写入 Golden 回归集，标注来源（真实任务 id 或构造）、可复现指令、参考解。
4. 验证命令写进该积木 tasks.md。

## 验证
- 每条测试可复现（同输入同输出）；金标准题双专家口径可判（或规则可判）。
- 回归集通过率不得低于 -2%（防退化）。

## 坑
- 不要用同一模型自评自己的测试（生成与验真解耦）。
- 隐藏 grader 风格：测试故意与 spec 矛盾的陷阱题，只放回归集、不放给实现者看。
