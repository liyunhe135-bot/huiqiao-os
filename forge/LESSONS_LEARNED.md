# 汇桥 OS 研发复盘账本：防 PRD 偏移与省流量高质量工程经验（LESSONS_LEARNED）

> **核心命题**：如何在严格控制云端大模型 Token 消耗的同时，确保最终产品体验与定版 PRD 零偏移？

---

## 一、典型偏移案例与三大根因

### 现象回顾
在 `M00–M11` 首轮冲刺中，底层 10 大积木的 155 项单元测试全部绿灯通过，但当真实用户首次打开工作台输入具体应用构建需求时，暴露出三处明显落差：
1. **缺少交互式设计阶段**：`PRD v3.0` 明确定义了 **SFDP 规格先行交付流水线（澄清门 → 规格工坊 → 构建 → 只读 AC 收敛 → 交付包五件套）**，首版界面却做成了单步直接提交；
2. **Mock 绿灯掩盖真机断层**：测试集全部采用内存脚本桩（Mock），未在生产入口默认自动探活并连接本机 Ollama 显卡推理服务；
3. **术语门槛过高**：首版国风赛博界面直接使用了较多佛学专业词汇（如止观、阿赖耶识、四摄），对普通公众不够直观。

### 根因剖析
1. **摘要卡漏斗失真（Over-Compression Drift）**：初期生成的 32 行极简上下文卡只提炼了 `PRD v2.2` 的模块表，遗漏了后来 `PRD v3.0（合并优化版）` 新增的 §5–§7 规格先行与五件套章节；后续会话为省流量只读摘要卡，导致遗漏被一路放大。
2. **测试替身幻觉（Mock-Only Green Illusion）**：单元测试测通了模块契约，却缺少「真实本地模型 + 真实浏览器从设计到点开运行产物」的端到端验收门。
3. **自嗨术语替代用户心智**：把内部状态机术语或小众专业词直接当作默认按钮文案，增加了首次上手的认知负担。

## 二、永久固化的四条防偏移工程铁律（低 Token 落地法）

| 编号 | 铁律名称 | 零/低 Token 具体执行动作 |
| :---: | :--- | :--- |
| **Rule 1** | **定版目录零 Token 差分核对** | 不必把几万字 PRD 塞进上下文，但建/改 `BRICK_CONTEXT_CARD.md` 时，必须用 10 行 Python 脚本提取 `docs/` 最新定版文档全部 `# / ## / ###` 标题做完整性核对，确保**省字数不漏章节**。 |
| **Rule 2** | **设计态 × 运行态双闭环必检** | 凡面向创造/编码/文件交付的功能，界面必须同时具备 **「先对齐可改规格（Design）」** 与 **「一键打开运行产物 + 查看五件套验收报告（Run）」** 两个闭环。 |
| **Rule 3** | **里程碑真机一票否决门** | Mock 单测用于秒级回归；但每次里程碑收尾必须实连本机推理服务，在浏览器走通至少 1 个真实用户案例并点开产物验证。 |
| **Rule 4** | **大众白话默认 × 风格语境可选** | 默认界面文案一律采用任何普通用户 1 秒能懂的科技白话；禅意/行业特色术语作为右上角可切换语境提供，且全部配悬停白话释义。 |
