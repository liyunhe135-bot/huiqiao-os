# 评审器（Review，便宜模型 + 规则清单）

## 触发
实现完成、交付包生成前。

## 输入
diff/变更清单 + spec（AC）+ 执行日志 + 自检报告。

## 步骤
1. **AC 逐条核验**：每条 AC 找到对应证据（测试输出/产物文件），缺证据即缺陷。
2. **风险清单过一遍**（规则化检查，非模型发挥）：
   - 单次改动是否 >400 行；是否动了范围外文件；
   - 有无删除/覆盖等不可逆操作及软删除措施；
   - 数据契约字段是否与冻结 schema 一致；
   - 失败路径/并发/越权是否覆盖（负例 AC 是否过）。
3. 输出缺陷清单：`[编号] 位置 | 问题 | 严重度(高/中/低) | 修复建议`。
4. 结论：`通过` / `打回（缺陷 N 条）`。

## 验证
- 缺陷清单逐条可定位（文件+行号）。
- 打回时指定「回到哪个 task」。

## 坑
- 评产物不评路径：只查最终状态/测试结果，不罚「实现路径与预期不同」。
- 用 Laborer 档评审，Brain 档只在缺陷争议时介入。
