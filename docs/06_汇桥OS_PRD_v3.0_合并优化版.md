## 1. 名称、定位与第零核心（定版）

- **项目名**：**汇桥 OS（HuiQiao OS）**，沿用 [README](../README.md) 与 v2.2 §1.1 的全部释义（水木相生、乐高汇聚、津梁托举、慈航普渡）。
- **五行补注（结合用户诉求）**：若希望补入「水 + 金」能量，可将**确定性验证与交付铸造成型**的子系统命名为独立代号（候选：**钧泽 / 铸泽 / 鉴泽**，均为金生水相生），作为汇桥的「金之骨」子品牌，不改动总名。
- **一句话定位（合并升级）**：汇桥 OS 是一套运行在个人本地电脑上、100% 离线可控的乐高积木式共生智能调度与自演化系统——对客户输入的问题，**通过「规格先行 + 代码构建」产出可审查、可验收、可回滚的完整交付物**，以 C00 众生和谐增上宪章为最高价值核心，确定性流程（金）与概率性创造（水）刚柔并济。
- **诚实能力契约（写进产品）**：✅ 承诺单函数/短脚本、结构化多步流程、文档/数据产物、抽取分类、单轮工具调用；⚠️ 有限承诺仓库级改代码与多步长程 agent（用规格拆解补偿）；❌ 不承诺云端旗舰级的开放世界自主探索，超范围显式降级（A5 知限谦卑）。

## 5. 规格先行交付流水线（SFDP，新增核心机制）

把「客户输入问题 → 完整交付物」固化为跨积木的标准协议（Spec Kit/OpenSpec 式，落地在 B02→B03→B05→B10）：

```
① 澄清门（≤5 个定向问题，答案写回 spec）
② 规格工坊：spec.md（what/why + 交付物定义 + 可观察 AC：给定/当/则+负例）
           + plan.md + tasks.md（依赖排序、编号任务、每步带验证命令）
③ 构建：B03 按 ADK 原语编排 → B05 Worker 在 B07 沙箱内执行
        （每步过 B10 证据闸门；高危操作 interrupt() 人工审批）
④ 收敛：converge 对照 AC 逐条核验；不通过 → 缺口追加为新任务再循环（只追加、不改码）
⑤ 交付：§6 交付包五件套
```

- **L0/L1 快速通道**：技能直通/确定性流可裁剪为精简版（spec 仅存参数卡，交付包精简为产物+变更清单）。
- **L2-C/L3**：完整 SFDP。设计依据：本地模型「写 spec 排名紧咬云端 Claude Code、17/17 隐藏检查与 Opus 持平」，而长程自主规划是短板（附录 B）——把难的长程规划拆成「短、结构化、每步可验证」的步骤。
- **L2-S 语义共生**：不走 SFDP 构建门，交付包 = 结构化产出 + 透明原理（UPLIFT_MENTOR 启发增上态）。

## 6. 交付包五件套（定版）

任何「交付型」任务完成时，必须产出（`workspace/runs/<task_id>/delivery/`）：

1. **产物文件**（代码/文档/表格/报告/网页等实际成果）；
2. **变更清单**（动了哪些文件/数据，逐条可审）；
3. **执行日志**（关键步骤、沙箱命令与退出码、报错与修复）；
4. **自检报告**（对照 spec 的 AC 逐条核验结果）；
5. **验收协议**（如何运行/打开、如何验收、如何一键回滚）。

配套：B10 钩子校验五件套齐全才允许进入「收敛」，缺件打回；交付后 1 秒低摩擦反馈（👍/✏️/🔄/💡，汇桥 v2.2 §3.4）挂载在交付包末尾。
